# ゲーム設計書 — SORT FACTORY（v3: 推理パズル）

## 0. ここまでの経緯
| 版 | 内容 | 試遊結果 |
|---|---|---|
| v1 | 流れてくる荷物をリアルタイムで仕分け | 面白くない・爽快感がない（判断が浅いのに急かされる） |
| v2 | レーンを崩して出荷を連鎖させる手順パズル | 爽快感が足りない（「解けた」という手応えが残らない） |
| **v3** | **手がかりから箱の位置を理詰めで確定させる推理パズル** | 再試遊で確認する |

v2 までの反省: 「うまくいった／いかなかった」はあっても、**自分の頭で答えにたどり着いた**という感覚がなかった。
v3 は「答えは1つ・当てずっぽう不要・一手ごとに理由がある」推理パズルにし、最後の1個を置いた瞬間に全トラックが出荷される山場を作る。

## 1. ルール（積み込みパズル）
n×n の倉庫にトラックが停まっている。次の3つをすべて満たすように箱を置く。

1. **トラック1台につき箱1個**。箱はそのトラックの上下左右のとなりに置く（箱とトラックは1対1）。
2. **箱どうしは隣り合わない**（ななめも不可）。
3. **外側の数字** ＝ その行・列に入る箱の数。

操作: マスをタップで「箱 → ×（箱なしのメモ）→ 消す」。なぞって連続入力も可。
時間制限なし、ミスの罰なし、失敗なし。箱の配置が正解と一致した瞬間にクリア。

※ 論理パズルの定番ジャンル（数字の手がかり＋配置制約）に属する。テーマ・見た目・演出・ヒントの仕組みは独自。

## 2. 「考えて解けた」を成立させる仕組み
- **解は必ず1つ**: 全ステージを総当たりで検証（生成時の Python と、テスト時の Dart の独立した2実装）。
- **当てずっぽう不要**: 生成時に人間と同じ推理ルールだけで解けることを確認し、必要な推理の段階（tier）を記録。
  - tier 1 数える: 「この列はあと2個、置けるマスも2個 → 確定」「このトラックの空きは1マスだけ → 確定」
  - tier 2 並びで決まる: 「3マス並びに2個 → 両はしで確定」
  - tier 3 もしもの推理: 「ここに置くと別の列が足りなくなる → ×で確定」
- **雑務は自動化**: トラックのとなりでないマス、箱のまわり8マス、満杯の行・列には薄い×が自動で付く。プレイヤーは推理だけに集中できる。
- **間違いはその場で見える**: ルール違反の箱は赤枠、数字は「達成＝緑／超過＝赤」。
- **ヒントは理由つき**: 答えを教えるのではなく「なぜそこが確定するか」を文章で示し、根拠の行・列・トラックを光らせる。間違った箱があればまずそれを指摘する（`lib/game/logic/deduction.dart`）。

## 3. 達成感の演出
- 行・列の数字がそろうと緑に弾んで効果音（小さな達成を積み重ねる）。
- **フィナーレ**: 最後の箱を置くと、箱が順番にトラックへ飛び乗り、トラックの色に染まって次々に走り去る。音程が1台ごとに上がり、最後に紙吹雪と「ALL SHIPPED!」。
- ★3 ＝ ヒントなしで解いた証。★が欠けたステージは「★3に挑戦」で再挑戦できる。

## 4. ステージ（30問）
`python3 tool/gen_stages.py` → `assets/stages/stages.json`（一覧は `docs/balance_report.txt`）。

| 区分 | ステージ | 盤面 | 必要な推理 |
|---|---|---|---|
| EASY | 1〜7 | 4×4〜6×6 | 数える（tier 1）。1〜3は練習（ヒント無料・★に影響なし） |
| EASY | 8〜10 | 5×5〜6×6 | 並びで決まる（tier 2）を導入 |
| NORMAL | 11〜20 | 6×6〜8×8 | tier 2 中心、14・16・17・19 で「もしも」（tier 3） |
| HARD | 21〜30 | 8×8 | tier 3 |
